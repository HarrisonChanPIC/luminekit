# Review returned corrections

Start from the prior finding's identity, witness/condition and required correction. Inspect the actual returned files and affected consumers or tests. An explanation, status label or disappearance from a list is not proof of resolution.

Accept any correct implementation permitted by the contract rather than a golden patch.

Match correction evidence to the current subject. A source correction can resolve that source defect while compiled-entry correspondence remains unverified; use the verification procedure of the `luminekit-engineering-change` skill when that distinction matters. Review unclear or contradicted feedback against the actual requirement before applying any separately authorized remedy.
