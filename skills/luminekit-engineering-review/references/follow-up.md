# Review returned corrections

Start from the prior finding's identity, witness/condition and required correction. Inspect the actual returned files and affected consumers or tests. An explanation, status label or disappearance from a list is not proof of resolution.

Give each material finding a justified disposition: addressed within a stated source/runtime scope, still present, regressed, superseded with evidence or unverified with a specific missing check. Preserve supplied IDs and keep new issues distinct. Accept any correct implementation permitted by the contract rather than a golden patch.

Match correction evidence to the current subject. A source correction can resolve that source defect while compiled-entry correspondence remains unverified; use [engineering verification](../../luminekit-engineering-change/references/verification.md) when that distinction matters. Review unclear or contradicted feedback against the actual requirement before applying any separately authorized remedy.
