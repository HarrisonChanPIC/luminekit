# Delegate bounded work and inspect the result

Use this procedure for delegation or independent contexts; the calling method owns its questions and assessment. Roles are responsibilities, not a required set of workers. Keep one proportional workflow for the parent task.

## Respect execution assignments

Direct work with optional delegation remains the default. An explicit task, selected profile or standing-program route may instead assign a **controller-only orchestrator**; the model's identity alone does not select that arrangement. Honor selected role combinations and exclusive responsibilities when deciding who performs each unit.

Select coordination scope with [Workflow's routing decision](../SKILL.md#choose-the-scope-of-coordination). Keep ordinary and tailored bounded work with the current agent unless an explicit assignment says otherwise. A profile may authorize task-based selection of a controller arrangement; a role/model table alone does not. Use the current session as controller when its actual model and assignment permit. Otherwise dispatch one eligible controller through supported tools with the outcome, accepted decisions, authority, resources and worker lifecycle responsibility. Keep the parent to the necessary handoff and user-facing relay rather than running a competing plan or fleet. Missing required controller capability leaves controller-dependent work pending; continue only work allowed by the retained assignment.

The controller-only orchestrator frames objectives and constraints, writes briefs, manages dependencies and resources, inspects actual artifacts and evidence, makes acceptance decisions and reports. It selects supported returned decisions and sends unresolved specialist choices back to workers. Delegate specialist investigation, architecture/module design, implementation, review/evaluation and executable verification, including test programs, documentation corrections, conflict resolution and integration edits. Controller inspection establishes its acceptance basis, not independent review coverage. Coordination records and the final report remain controller outputs.

Discretion chooses useful units and eligible workers within those boundaries; it does not transfer assigned specialist work to the controller. Combine worker responsibilities where useful without erasing required independence or review gates; no full fleet or distinct agent for every role is implied. A missing worker leaves dependent work pending while the controller continues permitted coordination. Changing the selected arrangement needs the user's direction, rather than an implicit fallback. These are execution instructions, not proof of native tool-permission enforcement.

## Select actual capabilities

Use current host instructions and exposed or discoverable tools to establish available capabilities. Native delegation is sufficient when it serves the task; additional host or cross-provider tools are conditional on the task and host rules. Follow current discovery frequency, tool selection, context/isolation, waiting and cancellation rules. Saved preferences and parent tool receipts do not prove child capabilities. Without usable delegation, complete supported work within the selected assignment and disclose missing coverage; direct execution is a fallback only where that assignment permits it.

Choose roles and supported model/settings from the assigned question's reasoning burden, uncertainty, useful independence, budget and user preferences. Model and reasoning effort are separate choices; select only exposed controls within the user's constraints. An absent effort control leaves effort unspecified. Validate exact target and option identifiers before dispatch; an unavailable explicit target is a gap, not permission for silent substitution. No fixed model, provider mix or worker count is required.

Match the host's launch-role field and any generated role instructions to the assigned responsibility. Use a compatible general role when no dedicated controller role is exposed; a design role can inject designer instructions despite an orchestrator brief. Inspect available launch instructions and receipts for conflicts. Report a discovered mismatch immediately, follow the user's cancellation/relaunch authority and retain the malformed attempt as limited evidence rather than treating it as a valid role check.

## Bound the assignment

Give each worker a coherent result, accessible source/revision and task grounding, assigned responsibility and execution boundaries, dependencies, controlling acceptance, permitted effects, output destination, stopping budget and useful partial return if blocked. Carry relevant selected model/effort constraints and review gates into the brief. Separate required coverage from optional expansion. Split where interfaces and acceptance permit independent progress; the controller coordinates dependent integration and assigns any specialist edits within the selected arrangement. A runnable discriminating slice can bound an authorized prototype before optional breadth; design coverage does not require implementing every component.

Match context to the role. Implementers receive selected decisions, concrete interfaces and any required plan-review disposition; resolve missing or blocking required review before dependent work and reuse sufficient existing coverage. Reviewers receive original controlling requirements separately from changed artifacts; the applicable domain review procedure owns acceptance authority. Supply suspected defects only for an explicitly targeted verification. Candidates and judges receive the calling method's independent framing. Keep unrelated history out and bound writable destinations so workers cannot overwrite one another. A brief creates neither access, isolation nor authority.

## Independent contexts

Use fresh contexts with equivalent authorized grounding for independent work; disclose material access differences without copying denied sources. Record fresh versus inherited history and sequential versus parallel execution. Inherited history limits the independence claim; fresh contexts can run sequentially when concurrency is unavailable. Serial controller-generated alternatives and fixed responses remain supplied material, without independent coverage.

Use the actual native or host schema rather than inventing invocation parameters. Keep requested provider/model/options distinct from known resolved controls and worker self-report. Record actual identities when known and leave unknown identity, effort or context history unknown. Consider available, permitted model diversity when it adds useful independence within the task budget; a single-model harness remains viable. Separate sessions establish no model diversity; a different model establishes no context isolation.

A separate judge or evaluator starts after the compared work has finished and receives the same controlling basis, exact actual outputs and missing-coverage information, without evaluator answers or a preferred verdict. Use a fresh context; without a separate evaluator, label controller review. The calling method owns the comparison criteria, not these execution safeguards.

## Accept actual results

Inspect actual source, artifacts and relevant checks against controlling acceptance before dependent work or synthesis. Verify named outputs at their actual destinations; summaries, confidence, self-tests and empty or stale receipts are insufficient acceptance. The controller owns integration accountability and the final claim; performing specialist synthesis, checks and corrections follows the selected execution assignment. Use the calling domain's verification procedure to determine meaningful checks and corrections.

Preserve actual briefs, output/context identities and inspected scope in existing receipts or a compact record. Distinguish completed, partial, failed, timed out, refused, truncated, cancelled and pending work. Inspect useful partial artifacts without promoting them to completion; silence or dropout is missing coverage, not a vote or clean review. Collect late results or disclose them as pending before closing scope. Supplied output remains supplied evidence.

Retry or replace only within the task budget and authority, keeping briefs and criteria comparable. Disclose legitimate input/criteria changes and reopen affected assessments. Preserve supported findings and verify corrections; the workflow's returned-work dispositions still apply.

## Evaluate resources at useful boundaries

Assess completed evidence, uncertainty, remaining work and resources before accepting, refining, splitting, narrowing or stopping a direction. Justify additional workers or context by the result needed; repeated redesign or recursive delegation does not replace decomposition.

For resource comparisons, account for coordination, investigation, design, candidates, implementation, review, judging, verification, integration, failed attempts, corrections and retries. Record available input/cached/output/reasoning usage with its measurement semantics, avoiding double counting; unknown usage is not zero. Separate elapsed time from summed worker time, actual billed cost from dated estimates, and subscription allowance from money. Include duplicated context, discarded work, integration rework and human intervention when material. Compare quality and resources through accepted completion under comparable conditions; a cheaper model label or smaller token ceiling alone establishes no efficiency gain. No universal numerical budget is implied.
