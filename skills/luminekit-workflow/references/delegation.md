# Delegate bounded work and inspect the result

Use this procedure for delegation or independent contexts; the calling method owns its questions and assessment. Roles are responsibilities, not a required set of workers. Keep one proportional workflow for the parent task.

## Select actual capabilities

Use current host instructions and exposed or discoverable tools to establish available capabilities. Native delegation is sufficient when it serves the task; additional host or cross-provider tools are conditional on the task and host rules. Follow current discovery frequency, tool selection, context/isolation, waiting and cancellation rules. Saved preferences and parent tool receipts do not prove child capabilities. Without usable delegation, complete supported work directly and disclose missing independent coverage.

Choose roles and supported model/settings from the assigned question's reasoning burden, uncertainty, useful independence, budget and user preferences. Model and reasoning effort are separate choices; select only exposed controls within the user's constraints. An absent effort control leaves effort unspecified. Validate exact target and option identifiers before dispatch; an unavailable explicit target is a gap, not permission for silent substitution. No fixed model, provider mix or worker count is required.

## Bound the assignment

Give each worker a coherent result, accessible source/revision and task grounding, dependencies, controlling acceptance, permitted effects, output destination, stopping budget and useful partial return if blocked. Separate required coverage from optional expansion. Split where interfaces and acceptance permit independent progress; retain dependent integration with the controller. A runnable discriminating slice can bound an authorized prototype before optional breadth; design coverage does not require implementing every component.

Match context to the role. Implementers receive selected decisions, concrete interfaces and any required plan-review disposition; resolve missing or blocking required review before dependent work and reuse sufficient existing coverage. Reviewers receive original controlling requirements separately from changed artifacts; the applicable domain review procedure owns acceptance authority. Supply suspected defects only for an explicitly targeted verification. Candidates and judges receive the calling method's independent framing. Keep unrelated history out and bound writable destinations so workers cannot overwrite one another. A brief creates neither access, isolation nor authority.

## Independent contexts

Use fresh contexts with equivalent authorized grounding for independent work; disclose material access differences without copying denied sources. Record fresh versus inherited history and sequential versus parallel execution. Inherited history limits the independence claim; fresh contexts can run sequentially when concurrency is unavailable. Serial controller-generated alternatives and fixed responses remain supplied material, without independent coverage.

Use the actual native or host schema rather than inventing invocation parameters. Keep requested provider/model/options distinct from known resolved controls and worker self-report. Record actual identities when known and leave unknown identity, effort or context history unknown. Consider available, permitted model diversity when it adds useful independence within the task budget; a single-model harness remains viable. Separate sessions establish no model diversity; a different model establishes no context isolation.

A separate judge or evaluator starts after the compared work has finished and receives the same controlling basis, exact actual outputs and missing-coverage information, without evaluator answers or a preferred verdict. Use a fresh context; without a separate evaluator, label controller review. The calling method owns the comparison criteria, not these execution safeguards.

## Accept actual results

Inspect actual source, artifacts and relevant checks against controlling acceptance before dependent work or synthesis. Verify named outputs at their actual destinations; summaries, confidence, self-tests and empty or stale receipts are insufficient acceptance. The controller owns integration and the final claim. Use the calling domain's verification procedure for meaningful checks and corrections.

Preserve actual briefs, output/context identities and inspected scope in existing receipts or a compact record. Distinguish completed, partial, failed, timed out, refused, truncated, cancelled and pending work. Inspect useful partial artifacts without promoting them to completion; silence or dropout is missing coverage, not a vote or clean review. Collect late results or disclose them as pending before closing scope. Supplied output remains supplied evidence.

Retry or replace only within the task budget and authority, keeping briefs and criteria comparable. Disclose legitimate input/criteria changes and reopen affected assessments. Preserve supported findings and verify corrections; the workflow's returned-work dispositions still apply.

## Evaluate resources at useful boundaries

Assess completed evidence, uncertainty, remaining work and resources before accepting, refining, splitting, narrowing or stopping a direction. Justify additional workers or context by the result needed; repeated redesign or recursive delegation does not replace decomposition.

For resource comparisons, account for coordination, investigation, design, candidates, implementation, review, judging, verification, integration, failed attempts, corrections and retries. Record available input/cached/output/reasoning usage with its measurement semantics, avoiding double counting; unknown usage is not zero. Separate elapsed time from summed worker time, actual billed cost from dated estimates, and subscription allowance from money. Include duplicated context, discarded work, integration rework and human intervention when material. Compare quality and resources through accepted completion under comparable conditions; a cheaper model label or smaller token ceiling alone establishes no efficiency gain. No universal numerical budget is implied.
