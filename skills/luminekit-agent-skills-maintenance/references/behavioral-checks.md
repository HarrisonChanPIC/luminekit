# Check decisions and activation

For independent checks, use the delegation and independent-work procedure of `luminekit-workflow`; maintenance comparisons do not require Arena's alternative-selection method.

Use fresh independent runs with and without the guidance for non-obvious deletions or guardrail rewrites. For maintenance, compare the retained current version with the revision; when a claimed no-op needs testing, also run the relevant task without that rule. A failed comparison reopens the affected deletion or rewrite. If the needed independent run is unavailable, retain the guidance whose removal depends on it and report the remaining check.

## Supply a realistic task

Use equivalent isolated inputs, permissions and available tools. Give the agent the user's natural request, necessary raw artifacts and discoverable guidance. Keep expected answers, suspected failures, proposed corrections and prior evaluator conclusions out of its context. For a creation task, compare with a no-proposed-guidance control before adopting a new behavioral prescription. Migration of an established user rule needs preservation evidence, not an invented baseline failure.

Choose cases for the decisions at stake, including a meaningful counterexample; no fixed run count or universal benchmark schema is required. A dependency edit may need both available and unavailable dependency cases. A consolidation may need the condition carried only by the removed copy. A resource change needs a task that actually reads, executes or uses it. Avoid grading incidental wording or headings.

Use the available authorized harness and its actual delegation capabilities. Keep each run's writable outputs separate and outside the shipped skill. Preserve the client/model, relevant settings, input and guidance versions, task, actual reads and resulting artifacts. A self-walkthrough can supplement these checks but does not count as an independent run. Disclose unequal access or execution gaps; do not silently substitute another provider or claim unavailable execution.

## Inspect the result

Inspect actual artifacts, tool actions and read paths as well as the agent's summary. Compare independent requirements and the relevant invariant across runs. Check whether the agent reached the procedure, preserved conditions, used genuine dependencies, respected task scope and left unavailable work pending. A green validator proves only its structural checks; loading a skill proves neither correct use nor a better result.

Test activation separately when names, descriptions or routes change. Offer the available descriptions with natural requests that should select the skill and close requests that should not. Distinguish a supplied-description selection test from native automatic discovery. Do not tell the selection agent which skill is expected. Test output quality with the selected guidance separately.

Change only what the evidence supports, then rerun the affected checks. Record adopted source guidance and deliberate omissions where they matter for maintenance. Keep test artifacts and source comparisons with the development evidence rather than adding them to every installed bundle.
