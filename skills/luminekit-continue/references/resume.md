# Recover against current sources

Resolve the current objective, instructions, workspace, relevant dirty state and permitted work. A status/next-step request ends with reconstruction, while a continue-work request may authorize the described work within its actual scope.

## With a checkpoint

Read captured claims as leads, then follow current owners, tracker, relevant artifacts and dependencies. Compare actual source/revision, dirty/configuration inputs and available outcomes with the note. Expose stale completion or unsupported claims; reuse still-valid context without replaying every old investigation. Current corrections and withdrawn permissions supersede recall.

## Without a checkpoint

Inspect accessible owners, artifacts/source, dirty-state metadata, original decision/change evidence and tracker. Reconstruct what current files establish, intended approved changes, remaining work and recorded checks. Preserve uncommitted changes as real inputs. Name unrecoverable unsaved hypotheses/corrections or attempts; an interrupted agent cannot be relied on to save retrospectively, and an absent note does not prove completion or nonexecution.

## Revalidate and continue

Relate needed results to actual source/artifact/revision/configuration and coverage. Recheck only affected evidence after an input changes, retaining unrelated valid results within their limits. For a reader-context change use [recipient access](recipient-access.md).

Return verified state, corrected reports, remaining unknowns and next supported action. Actual fresh-reader reconstruction establishes that bounded resumption; it does not restore hidden session history. Use [capture](capture.md) only for a real gap and [boundary recommendation](boundaries.md) when a fresh context would answer a concrete unresolved question.
