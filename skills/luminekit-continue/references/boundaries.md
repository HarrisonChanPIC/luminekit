# Handle context pressure and useful boundaries

Use when available host usage telemetry signals context pressure, a capacity warning arrives, concrete symptoms show lost working state, or a person/session change or ineffective investigation gives a reason for fresh context. When usage is exposed, use roughly **50% of the effective context capacity used** as the default trigger to checkpoint and compact at the next safe boundary, unless the user or host sets another threshold. Capacity pressure is a valid reason even while work remains coherent. Without usage telemetry, use available warnings or concrete symptoms; do not invent a percentage, infer it from turn count, assume the model's advertised window is the harness's effective capacity or require polling.

1. Identify the signal and unfinished objective, latest corrections and next useful boundary. Keep long raw logs/diffs in accessible artifacts and retrieve bounded relevant portions rather than carrying them repeatedly in context. Distinguish an actual host signal from a supplied-warning simulation or inference.
2. At a safe useful boundary, use [capture](capture.md) for otherwise missing recovery state before capacity is exhausted when signals allow. Existing owners may suffice; preserve active workers and completed valid work. For ineffective approaches, use the task's diagnosis procedure before merely moving an unresolved failure. Capacity handling itself needs no diagnosis of confusion, pause or new approval gate.
3. Use actual native/host compaction when exposed and permitted, preserving useful automatic host behavior. Follow its real lifecycle and authority rules. A note is not a compaction control; do not invent a command, endpoint, hook or configuration change. If no usable control is exposed, prepare a concise recoverable checkpoint and use an available authorized fresh-context/resumption path. If none is available, report preparation and the missing control without claiming a context reset. Continue supported authorized work where feasible.
4. After the transition, use [recover](resume.md) against current sources. Report recommended, checkpoint prepared, native compaction observed and fresh-reader resumption distinctly. A compacted author/candidate remains that author/candidate, not an independent reviewer or judge.

These rules apply in a single harness; optional host delegation is not a prerequisite. No cross-harness autonomous-compaction guarantee follows from a checkpoint or one successful resumption. Abrupt termination cannot guarantee a final save. A concise resolved result can finish without a session migration.
