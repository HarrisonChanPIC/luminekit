# Recommend a useful context boundary

Use when a person/session change is relevant or repeated failures/corrections and growing irrelevant investigation give a concrete reason for fresh context. A coherent task with recoverable state needs no recommendation; length or turn count alone does not diagnose confusion.

1. Identify the current objective, material correction, unfinished question and reason another context could help: a coherent subtask boundary, persistent ineffective approach, unrelated accumulated investigation or recipient change.
2. Continue available supported work and use the task’s diagnosis procedure for an unresolved failure before merely moving it to another context. Recommend a checkpoint/fresh context only with that reason and a bounded next question; the recommendation itself is no pause, abandonment or approval gate.
3. If otherwise missing state needs capture, use [capture](capture.md). Existing owners/tracker may already suffice. Report recommended/prepared/done distinctly.

Use telemetry, compaction, clear/resume commands or hooks only when the actual host exposes them and current authority permits use. Do not assume a model-window threshold or claim a note clears context. Hooks cannot guarantee a final write after abrupt termination. A concise resolved result can finish without a session migration.
