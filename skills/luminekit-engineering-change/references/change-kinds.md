# Change kinds

- **Feature:** implement the requested observable behavior at the existing appropriate boundary, including necessary setup and documentation.
- **Fix:** distinguish the symptom, supported cause and remedy. Use [test-first](test-first.md) when practical or requested; otherwise use independent [verification](verification.md) and report its limits.
- **Refactor:** preserve behavior and compatibility across actual callers, data and runtime boundaries with meaningful parity checks. An existing-record migration needs established identity/reference rules, recoverable state and an appropriate rollout before destructive steps.
- **Prototype:** answer a named uncertainty within the authorized experiment scope, cost and decisive observation. Report the answer, production gaps and agreed artifact disposition.

Preserve public behavior outside the selected change and relevant failure, cancellation and resource semantics. If a failed remedy exposes an unsupported cause, return to [Diagnosis](../../luminekit-diagnose/SKILL.md) before another dependent adjustment.
