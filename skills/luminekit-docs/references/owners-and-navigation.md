# Choose owners and navigation

Start with a representative reader outcome, such as locating setup steps, changing one feature or finding current commercial terms. Follow the existing route before designing another. Use [source-backed authoring](source-backed-authoring.md) only for genuinely missing knowledge; an accurate, discoverable, appropriately focused route can remain unchanged.

Give each operative proposition one current owner. Reuse established locations, titles and naming conventions. Otherwise choose a small permitted entry and useful owners. Keep official identifiers, revisions and original/export lineage; reorganizing guidance is not a reason to bulk-rename received records.

## Place content by reader task

Decide placement before drafting substantial additions or expanding a mixed section. Ask whether readers need the material to choose their next step or only after choosing a task. A shared domain or audience alone does not make two procedures one task. Extract independently needed concerns even when the file is short; size is not the trigger.

| Content | Owner |
| --- | --- |
| Purpose, scope, task selection and brief shared prerequisites | Entry or index |
| Current task-specific behavior, definitions, procedures and constraints | Focused owner behind a conditional link |
| Prerequisites, exceptions, failure handling and recovery | The procedure they qualify, or an explicit required dependency at the relevant step |
| Current and approved-future versions of the same rule | Its focused owner, with applicable periods explicit |
| Consequential rationale, useful rejected alternatives and reintroduction conditions | Separate decision/rationale owner, linked when that question is relevant |
| Contextual history, implementation chronology, review logs and run evidence | Existing work/evidence locations outside current guidance |
| Controlled originals and received records | Controlled locations retaining identity and access |
| Unfinished work and task status | Existing work owner or tracker |

Keep an operative constraint in current guidance even when a separate historical decision explains its origin. Necessary source/revision pointers and current qualifications stay beside their claims. Current procedures must remain usable without reading historical originals or ignored work files. Preserve useful rationale and controlled records without creating an archive for every edit.

Prefer nested, conditional links to independent tasks over inline detail. Each route states when to open its target and what it owns rather than copying its rules. Keep tightly coupled instructions together; do not fragment a coherent procedure to meet a count. A heading link inside a compulsory monolith is not extraction. Add a directory index only when it reduces navigation work, without empty intermediate layers or placeholders.

Follow only the relevant branch and necessary dependencies; do not prefetch every link. Stop when the reader's task is answered. An actual evidence investigation may need source records that an ordinary operating task does not.

| Situation | Placement decision |
| --- | --- |
| One guide mixes setup, artwork rules, economic rules and release history | Keep a short task map; extract the three current tasks into focused owners and place history outside current guidance |
| Setup includes a required migration condition, failure exception and rollback | Keep the complete procedure together; length alone does not justify splitting it |
| Import requires stable identifiers because earlier naming schemes failed | Keep the identifier requirement in the import procedure; link the rejected schemes from a separate rationale owner |

## Keep indexes useful as work grows

A work index or roadmap also owns brief status, dependencies, exit criteria and the next action. When a unit's substantive plan, design rationale or acceptance evidence would turn that entry into a detailed work record, move the detail to a focused linked work owner in the same update. After completion, update the index summary/link and keep the actual evidence with its unit. Permanent operating guidance follows the placement rules above rather than accumulating progress reports.

Separate a substantial decision comparison or shared preparation record when it serves a distinct reader task; do not repeat it across owners. Use project naming/location conventions and preserve incoming links, complete conditions and useful rationale during the move. A short coherent plan needs no extra index or files, and future units need no empty placeholders.

## Migrate and verify the route

When moving guidance, map useful propositions and known incoming routes before shortening the old entry. Current instructions should reach their owners without requiring historical originals; preserve those originals and useful rationale in their controlled locations. [Migration/application](migration-and-application.md) handles actual moves/replacements.

Read the resulting entry and required destinations in the actual host/link surface, including spaces and anchors. Use the `luminekit-docs-review` skill’s structure-and-evidence procedure for link/owner defects and its reading-cost procedure when claiming a reduction. A small owner/route table is sufficient unless repeated use demonstrates a registration need. File existence does not establish automatic host loading.
