# Apply a bounded documentation migration

Use for authorized replacement, move or removal of guidance. The `luminekit-workflow` skill supplies general scope, input/current-target and recovery safeguards. This procedure adds the preservation order needed when knowledge changes owners.

## Bind the migration

Identify the selected root, changed input paths, new/replaced/moved/removed destinations and known incoming pointers. Include current uncommitted inputs. Map complete useful propositions and unique rationale to final owners before shortening the old entry; proposition comparison in the meaning-and-retrieval procedure of the `luminekit-docs-review` skill defines that check. Controlled records keep their identity and access independently of the ordinary guidance route.

Use [content placement](owners-and-navigation.md#place-content-by-reader-task) to distinguish destinations for current instructions, rationale and work/evidence. Preserving useful meaning does not require retaining its original inline arrangement. Keep current guidance usable without historical originals or ignored work files; retain necessary conditions at the point of use and preserve unresolved discrepancies explicitly.

## Apply and verify

1. Preserve exact path/before-bytes for existing documentation being changed in the permitted recovery location. Verify recovery correspondence before replacement. A new-file-only migration records created paths instead of copying untouched originals.
2. Recheck affected inputs and destination state against the proposal. Resolve a changed input or occupied destination before its dependent move/replacement; preserve newer bytes rather than guessing a merge.
3. For structural extraction, first move the selected text without editorial rewriting. Account for retained text at its destinations and record every omission, intentional duplication and necessary adaptation, such as changed links or frontmatter. Compare complete propositions as well: line coverage can expose loss but cannot establish correct scope or meaning. A source-only reconstruction is different work and must not be reported as a lossless migration.
4. Read back the established owners and repair affected routes together. Verify preservation before a separately authorized wording improvement; keep the structural result available for comparison if both are requested. For a move, inspect known incoming pointers and disclose unseen scope. A write receipt or checksum cannot substitute for preserved meaning.
5. Remove an old entry only after useful meaning and required retrieval have been verified at its destination. If application stops partway, report changed/unchanged/uncertain paths and retain recovery until the conflict or verification gap is resolved.

Report actual migration scope, checked destinations, retained recovery and unresolved dispositions. Manual comparisons/copies do not lock files or make a multi-file migration atomic.
