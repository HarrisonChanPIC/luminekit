# Author a focused concept

Read for selected OKF authoring or revision, using [reading semantics](okf-reading.md). Choose a real bundle boundary; all non-reserved Markdown inside it needs parseable YAML frontmatter and a nonempty string `type`. Ordinary scratch outside that boundary needs useful navigation, not mandatory OKF. Agent Skills metadata remains its own format.

Search the selected owners for the same subject, entity and effective period before creating a concept. Update an adequate owner; link distinct roles instead of maintaining duplicate facts. Keep an accurate substantive description on rerun. Write supported knowledge, with complete conditions, exceptions and necessary source locators; no empty scaffold or invented architecture, terms or rules. Use [source-backed authoring](source-backed-authoring.md) and [placement](owners-and-navigation.md#place-content-by-reader-task).

`type` is the only always-required field. `title`, a distinguishing one-sentence `description`, `resource` for a real asset and short-string-list `tags` are recommended/optional. Use the selected [catalog](catalogs.md) for vocabulary; unfamiliar values are valid. Default to standard fields and Markdown. Preserve received unknown keys and native memory writer types without copying foreign extensions into new templates. A separately requested domain extension needs the catalog's sparse exception process; no separate creation-date field is introduced.

Use optional metadata only for supported information:

- Each `sources` entry requires `resource`, a path/URL or scope descriptor. Stable `id` keys join claim footnotes to sources. Retain revision/page/sheet/section qualifications beside the claim; moving a source does not change its identity.
- `generated` requires `by` within the family. For newly authored content or an actual meaningful revision, obtain the current instant from an available clock and record `at` with an explicit UTC offset when recording generation. The user need not supply that time. The spec does not separately mark `generated.at` required: preserve a received by-only mapping and keep unknown historical times unknown. An unavailable clock is a disclosed limit, not a reason to invent an instant. Resolve a human alias from the saved project instruction choice and a machine actor from reliable runtime information. Use a known producer/version, supplied `human:<id>` or `process:<id>`; omit optional families rather than invent identity/model version. Never infer personal details or attribute agent-written content to the requesting user.
- `verified` uses event mappings with `by` and `at`; a bare mapping is supported. Record only checks actually performed and their scope/revision in context, obtaining the check time from an available clock. Generation is not verification. Preserve historical checks without implying they confirm changed claims.
- Use `draft` for not-yet-reviewed/possibly incomplete content, `stable` for ready-to-consume content and `deprecated` for retained history that is no longer current. Absent status defaults to stable; it does not establish a verification event. Document lifecycle is separate from business approval and task progress. Optional `stale_after` is an absolute revalidation instant, not a value to refresh on every edit. All timestamp fields use ISO 8601 with explicit UTC offset.
- Source `author`, `usage_count`, `last_modified` and shared/per-source `usage_window: {from, to}` carry objective signals when known. Do not invent trust scores or usage data.

For an update, distinguish a meaningful content edit, a formatting-only edit and a new confirmation without rewriting. Update `generated` for the actual meaningful change when attribution is available; formatting alone need not advance it. A performed confirmation adds a `verified` event without requiring regeneration. Record the actual checked source/revision, claim scope, method and material limits in ordinary nearby context; metadata alone cannot carry them. A source check can support a scoped verification; a syntax/link check alone cannot verify every factual claim. A human request or general acceptance supplies no invented human check. Preserve prior events with their historical scope and qualify changed claims; do not imply an old human review covers a new agent edit. [Worked events](okf-examples.md#generation-and-verification) illustrate these decisions.

Use headings, lists, tables and fenced code where they make claims readable. No fixed body template is required. `# Schema`, `# Examples` and `# Computation` have conventional meanings when applicable. Links can be relative or leading-slash bundle-relative; the latter is recommended for move stability. Put relationship meaning in the surrounding sentence. Avoid a path form the receiving host interprets differently without an explicit route explanation.

An optional `index.md` lists directory concepts/subdirectories grouped by headings, each with a selection description. Copy a concept's approved description into its entry rather than inventing a competing factual summary. No index frontmatter, except root `index.md` may contain `okf_version: "0.2"`. Do not use reserved filenames for concepts. Optional `log.md` has no concept frontmatter: use flat entries grouped under real `YYYY-MM-DD` headings newest first; leading bold action labels are optional. Logs record useful history, not a mandatory edit ritual.

Update affected index descriptions, routes and provenance with authorized content/move changes. Retain small ubiquitous facts and necessary safety conditions at the actual entry where repeated extraction would cost more reading. Compare complete propositions and actual reader paths using `luminekit-docs-review`; a green metadata check or shorter file alone proves no retrieval benefit. Preserve source disagreements rather than silently normalizing them.

For Attested Computation authoring/consumption use [its contract](okf-computations.md). For worked engineering, business, custom-type and native-memory cases use [examples](okf-examples.md). A legacy migration is separately authorized work: `timestamp` maps to `generated.at` only with a supported actor/context; body Citations move to `sources` with stable claim keys. Preserve unknown metadata, historical evidence and meaning instead of mechanically rewriting every file.
