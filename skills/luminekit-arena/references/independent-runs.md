# Independent work: frame, isolate and collect

This is the shared execution procedure for independent candidate, reviewer and judge contexts. The caller's method owns what to ask and how to assess the results. Serial self-generated alternatives and fixed responses can be useful supplied material, but do not establish independent work.

## Before dispatch

Fix the purpose, subject/question, source/revision identity, constraints, public acceptance, permitted effects and stopping budget before outputs. Use the [candidate brief](../assets/candidate-brief.md), or reuse an equivalent one. Give contexts equivalent authorized grounding and disclose material access differences; do not copy denied sources to equalize them.

Choose roles from actual capabilities and the harness's instructions. Dispatch the constructed brief into a fresh context. A reviewer gets a suspected defect only when explicitly verifying it. Record actual fresh versus inherited context and sequential versus parallel execution. If history is inherited, disclose the contamination and limit the independence claim.

Use different model families when available and permitted; separate sessions alone establish no model diversity. Record actual provider/model identities when known. Honor requested model/settings constraints; an unavailable selection is a gap, not permission to substitute it silently.

| Harness capability | Mapping |
| --- | --- |
| Codex native agents | `spawn_agent` with a fresh context (`fork_turns: "none"` where supported) |
| Claude Code native agents | `Agent` with a self-contained task |
| Cursor / OpenCode native agents | `Task` / `task`, using the exposed schema |
| Host-provided delegation | The host's documented delegation tool and context/isolation controls |
| No usable independent tool | Work serially yourself; label the result controller-generated, without independent candidate or judge coverage |

These mappings identify capabilities, not required runners or tool parameters to invent. Apply the current harness's selection, wait and cancellation rules. Separate fresh contexts can run sequentially when concurrency is unavailable.

Bound writable output destinations so participants cannot overwrite each other's work. A brief does not create tools, isolation, access or authority the context lacks.

## Collect and hand back

Preserve actual output/context identities and inspected scope. Distinguish completed, partial, failed, timed out, refused, truncated, cancelled and pending work; silence/dropout is missing coverage, not a vote or clean review. Collect late results or disclose them as pending before closing the selected scope. A supplied response remains supplied evidence.

Retry or replace only within the actual task budget, keeping the relevant brief and criteria comparable. Disclose input changes and reevaluate affected results when criteria are legitimately corrected. Without usable independent capability, return supported work with its reduced claim instead of inventing contexts or spinning in tool calls.

A separate judge starts after candidates finish and receives the same controlling basis, exact actual outputs and missing-coverage information, without evaluator answers or a preferred verdict. Otherwise label controller review. Return the actual brief, output/context identities and known model/execution limits to the caller's comparison or finding-verification procedure.
